# 참고 영상 정리 3: 「컨설팅 200건 하던 회사가 하룻밤에 AI 올인을 결심한 이유」(아크포인트 오태완)

- 출처: 빌더 조쉬 채널, https://youtu.be/B2-hh1NSEFc (47분, 2026-10-12 공개)
- 앞의 두 영상이 "무엇을 팔고 어떻게 파는가"였다면, 이 영상은 "만든 것이 자산인가 슬롭인가"와 "노하우가 회사에 쌓이는가"에 대한 기준

## 1. 영상 요약(교수님 사업과 관련된 부분만)

| 주제 | 내용 |
|---|---|
| 슬롭의 함정 | 토스 앱 10개, 웹사이트 30개를 만들었지만 대부분 아무도 쓰지 않았다. 이유는 **배포 채널이 없어서**. 있어 보이는 에이전트·봇도 마찬가지 |
| 슬롭 판정 기준 | ① 계속 쓰이고 계속 개선되는가 ② 실제 임팩트(돈·시간·비용)가 났는가 ③ 병목을 없앴는가, 아니면 다른 사람에게 옮겼는가(AI 회의록: 쓰는 시간 10분을 아끼고 읽는 시간 10명×10분을 늘림) ④ AI 네이티브로 다시 설계했는가, 아니면 기존 방식에 AI를 살짝 묻혔는가 |
| 고객을 먼저 찾는다 | 아이디어 → 제품 → 고객 순서가 아니라, 고객사를 먼저 확보하고 그에 맞춰 제품을 만든다. 사업 위험이 크게 줄어든다 |
| 회사의 뇌 | 모든 문서·결정·회의가 AI가 읽을 수 있는 한 곳에 쌓인다(쿼리어블). "왜 신사업 B를 접었지?"에 회사 기준으로 답한다 |
| 노하우 승격 | 직원이 AI 세션에서 얻은 노하우 중 좋은 것을 대표가 골라 전사 스킬로 승격. 직원이 나가도 도메인 지식이 회사에 남는다 |
| 3단계 | 쿼리어블(조회 가능) → 에이전틱(실행) → 클로즈드 루프(노하우가 다음 업무에 자동 적용) |
| 언섹시 비즈니스 | AI 제품을 만들지 말고 전통 업종(지방 소기업·자영업)의 문제를 AI로 직접 해결해 주고 수익의 일부를 받는다 |

## 2. 우리가 만든 것의 슬롭 점검

영상의 네 기준으로 지금 저장소의 앱 6개를 점검한 결과.

| 앱 | 쓰이는가 | 돈이 나는가 | 판정 | 조치 |
|---|---|---|---|---|
| `coach.html` AI 면접 코치 | 숨고 결제 학생이 이용 코드로 사용 | 기본형·검수형 판매 | 자산 후보. **견적 20건·리뷰 10건 전까지는 미확정** | 배포 채널(숨고·크몽·블로그)에 집중 |
| `apply.html`·`studio.html` 신청서·작업실 | 교수님이 매 건 사용 | 정밀형·패키지 제작 도구 | 자산. 병목(교수 제작 시간)을 실제로 줄임 | 정답 갱신 기록으로 계속 개선 |
| `soomgo.html` 숨고 응답기 | 요청마다 사용 | 견적·전달·리뷰 문안 | 자산 | 성사율 기록이 쌓여야 판단 완성 |
| `interview.html` 면접 대비 노트 | 학생이 **무료로** 답변 초안을 만들 수 있음 | 없음 | **페이월 구멍.** 유료 기본형과 같은 일을 무료로 함 | **2026-10-12 수정: 답변 만들기에 같은 이용 코드 적용** |
| `index.html` 입시 문의 자동답변 | 입학처 직원이 실제로 쓰는지 확인 안 됨 | 없음(내부 도구) | **확인 필요.** 쓰지 않으면 슬롭 | 교수님이 답할 것: 지난 한 달 입학처에서 몇 건 썼는가. 0건이면 첫 화면에서 내리고 보관 |
| `coach-admin.html` 관리 화면 | 교수님만 사용 | 코드·해시 생성 | 자산(운영 필수) | 없음 |

결론: 앱은 충분하다. 영상의 오태완 대표가 깨달은 것과 같다. 지금 부족한 것은 앱이 아니라 **배포 채널과 실제 거래**다. 앞으로 새 앱을 만들기 전에 위 표의 네 질문을 먼저 한다.

## 3. "회사의 뇌"는 이미 있다. 쌓는 규칙만 지킨다
- 교수님의 뇌는 이 저장소다. `js/coach/framework.js`(평가 기준), `docs/`(결정과 근거), `data/questions.json`(공개 문항), 크몽·숨고·논문진단 스킬(일하는 방식)이 모두 한 곳에 있다.
- 영상의 "과정을 쌓지 않고 결과만 쌓는 실수"를 피한다. 가격을 바꾸거나 상품을 접을 때 **왜**를 `docs/` 메모에 한 줄이라도 남긴다. 나중에 "왜 간편형을 없앴지?"에 답할 수 있어야 한다.
- 노하우 승격 = `docs/정답-갱신-기록.md` 5건 → `framework.js` 반영. 이것이 교수님 사업의 클로즈드 루프다.

## 4. 적용하지 않는 것
- 지방 소기업 AX, 수익 배분 모델: 교수님의 전문성(임상병리·입시·교육)과 겹치지 않는다. 다만 같은 구조의 가까운 후보가 하나 있다. **다른 대학 입학처에 입시 문의 자동답변을 제공하고 연 사용료를 받는 것.** 고객(타 대학 입학처장)을 먼저 확보하고 맞춰 만드는 순서라면 영상의 공식과 맞는다. 겸직은 2026-10-13 총장 승인으로 해결됐으나, 아는 입학처장에게 묻는 방식은 쓰지 않는다(지인·직책 비이용 원칙). 하게 된다면 공개 채널(뉴스레터·블로그)을 보고 문의가 오는 경우에만 검토한다. 지금은 보류.
- 매일 아침 1시간 스터디, 직원 10명 세션 관리: 1인 운영에는 해당 없음.

## 5. 오늘 바뀐 것
- `interview.html`의 답변 만들기·기존 노트에 추가·전체 답변 다시 만들기에 이용 코드 페이월 적용. 문항 입력과 재료 작성은 그대로 열어 둠.
- 페이월 코드를 `js/coach/access.js`로 분리해 두 앱이 같은 코드·같은 대화상자를 씀.
